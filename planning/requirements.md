# Service Requirements

## 1. Purpose

본 문서는 첫 주식 구매 경험 개선안의 핵심 기능과
사용자 흐름, 노출 조건, 예외 상황 및 구현 범위를 정의한다.

본 프로젝트는 기존 증권 서비스 전체를 재설계하지 않는다.

기존의

`종목 탐색 → 정보 확인 → 구매 → 주문 확인`

흐름을 유지하면서,

첫 구매 사용자가

- 현재 어떤 정보를 확인할 수 있는지
- 해당 정보가 어떤 역할을 하는지
- 주문 과정에서 자신이 무엇을 선택하고 있는지

이해할 수 있도록 필요한 구간을 개선한다.


---

# 2. Target Scenario

## User

주식 매수 경험이 없거나
증권 서비스의 투자정보와 주문 방식을
스스로 해석할 기준이 충분하지 않은 사용자


## Situation

사용자가 삼성전자 1주를 처음 구매하려고 한다.


## Goal

사용자는 별도의 금융용어 검색이나
도움말 탐색에 의존하지 않고,

필요한 정보를 확인한 뒤
자신이 선택한 주문 방식과 주문 내용을 이해하고
구매 과정을 진행할 수 있어야 한다.


---

# 3. Core User Flow

전체 흐름은 다음과 같이 구성한다.

`종목 상세 진입`

↓

`첫 구매 안내 노출`

↓

`안내 이용 여부 선택`

↓

`구매 전 확인 가능한 정보 탐색`

↓

`구매하기`

↓

`주문 방식 이해 및 선택`

↓

`수량 입력`

↓

`주문 내용 확인`


첫 구매 안내를 이용하지 않는 경우에는

`종목 상세 → 구매하기 → 기존 주문 흐름`

으로 바로 이동할 수 있어야 한다.


---

# 4. Functional Requirements

## FR-01. First-Purchase Guide Entry

### Purpose

첫 구매 사용자가
종목 상세에서 제공되는 정보를
어떻게 살펴볼 수 있는지 안내한다.


### Trigger

사용자가 종목 상세 화면에 진입했을 때
첫 구매 안내를 선택적으로 제공한다.


### Required Information

안내에는 다음 내용이 포함되어야 한다.

- 첫 구매 사용자를 위한 안내임을 알 수 있는 제목
- 구매 전 확인 가능한 정보를 살펴볼 수 있다는 설명
- 안내 시작
- 안내 건너뛰기


### Example

> **처음 구매하시나요?**
>
> 구매 전에 어떤 정보를 확인할 수 있는지
> 간단히 살펴볼 수 있어요.
>
> `살펴보기`
>
> `괜찮아요`


### User Control

안내 이용 여부는 사용자가 직접 선택한다.

안내를 이용하지 않아도
기존 종목 상세와 구매 기능을
정상적으로 사용할 수 있어야 한다.


---

# FR-02. Information Role Guide

## Purpose

첫 구매 사용자가
종목 상세에 제공되는 여러 정보가
각각 무엇을 확인하기 위한 정보인지
구분할 수 있도록 한다.


## Information Categories

프로토타입에서는 다음 세 가지를 우선 안내한다.


### 1. 가격 변화

사용자가 현재 가격과
최근 가격 움직임을 확인할 수 있는 영역

Example:

> **최근 가격이 어떻게 움직였는지**
>
> 현재 가격과 최근 가격 변화를 확인할 수 있어요.


### 2. 최근 정보

최근 기업 관련 뉴스나
주요 이슈를 확인할 수 있는 영역

Example:

> **최근 어떤 일이 있었는지**
>
> 기업과 관련된 최근 뉴스와
> 주요 정보를 확인할 수 있어요.


### 3. 기업 정보

기업의 기본 정보와
실적 등을 확인할 수 있는 영역

Example:

> **어떤 회사인지**
>
> 기업의 기본 정보와
> 실적 등을 확인할 수 있어요.


## Requirement

안내는 특정 정보를
반드시 확인하도록 요구하지 않는다.

각 정보의 역할을 설명하고
어떤 정보를 확인할지는
사용자가 직접 결정할 수 있어야 한다.


---

# FR-03. Purchase Entry

## Purpose

정보 탐색 이후
사용자가 기존 구매 행동으로
자연스럽게 이동할 수 있도록 한다.


## Requirement

종목 상세에는
명확한 `구매하기` 행동이 유지되어야 한다.

정보 안내를 이용한 사용자와
이용하지 않은 사용자 모두
동일한 구매 단계로 이동한다.


## Constraint

안내를 완료해야만
구매할 수 있도록 제한하지 않는다.

사용자가 원하는 시점에
구매 단계로 이동할 수 있어야 한다.


---

# FR-04. Order Method Explanation

## Purpose

첫 구매 사용자가
주문 방식의 이름만 보고 선택하는 것이 아니라,

각 선택에 따라 무엇이 달라지는지
현재 화면에서 이해할 수 있도록 한다.


## Required Options

프로토타입에서는
첫 구매 상황에서 비교가 필요한
두 가지 기본 주문 방식에 집중한다.


### Option A

**현재 거래 가능한 가격을 기준으로 구매**

Description:

> 가격을 직접 정하지 않고
> 현재 거래 가능한 가격을 기준으로 주문해요.
>
> 시장 상황에 따라 실제 체결 가격은 달라질 수 있어요.

Secondary Label:

`시장가`


### Option B

**원하는 가격을 직접 정해서 구매**

Description:

> 구매하고 싶은 가격을 직접 정해요.
>
> 해당 가격에 거래가 가능할 때 체결되며,
> 조건이 맞지 않으면 바로 체결되지 않을 수 있어요.

Secondary Label:

`지정가`


## Requirement

전문용어를 제거하는 것이 아니라
행동의 의미를 먼저 이해할 수 있도록 구성한다.

전문용어는 사용자가
기존 증권 서비스의 용어와 연결할 수 있도록
보조적으로 함께 제공한다.


---

# FR-05. Quantity Selection

## Purpose

사용자가 구매하려는 수량과
예상 주문 금액을 명확하게 확인할 수 있도록 한다.


## Required Information

- 종목명
- 현재 선택한 주문 방식
- 주문 가격 또는 가격 결정 방식
- 구매 수량
- 예상 주문 금액


## Requirement

수량을 변경하면
예상 주문 금액에도 변경 결과가 반영되어야 한다.


## Prototype Scope

대표 시나리오는
삼성전자 1주 구매를 기준으로 한다.


---

# FR-06. Order Review

## Purpose

최종 주문 전에
사용자가 자신이 선택한 내용을
다시 확인할 수 있도록 한다.


## Required Information

최종 확인 화면에는 최소한 다음 정보를 제공한다.

- 종목명
- 구매 수량
- 주문 방식
- 주문 가격 또는 가격 결정 방식
- 예상 주문 금액


## Contextual Confirmation

주문 방식은 전문용어만 표시하지 않는다.

Example:

> **현재 거래 가능한 가격을 기준으로 구매**
>
> 시장가


또는

> **원하는 가격을 직접 정해서 구매**
>
> 지정가


## Requirement

사용자는 최종 단계에서

'어떤 종목을 몇 주 구매하는지'

뿐 아니라

'어떤 방식으로 주문하는지'

확인할 수 있어야 한다.


---

# 5. Information Hierarchy

서비스에 제공되는 정보는
다음 세 단계로 구분한다.


## Level 1. Action Information

현재 구매 행동을 수행하기 위해
직접 확인해야 하는 정보

- 종목
- 가격
- 수량
- 주문 방식
- 예상 주문 금액


## Level 2. Decision Context

사용자가 자신의 판단을 위해
선택적으로 확인할 수 있는 정보

- 최근 가격 변화
- 최근 주요 정보
- 기업 기본정보
- 실적


## Level 3. Advanced Information

필요한 사용자가
추가적으로 탐색할 수 있는 전문정보

- 상세 차트
- 호가
- 체결정보
- 이동평균선
- 거래동향


## Requirement

Level 2와 Level 3 정보는
사용자의 투자 판단을 대신하지 않는다.

서비스는 정보의 역할을 안내하며
실제 확인 여부와 투자 판단은
사용자가 결정한다.


---

# 6. User Control Requirements

## UC-01. Guide Skip

사용자는 첫 구매 안내를
선택하지 않고 기존 흐름을 이용할 수 있어야 한다.


## UC-02. Free Exploration

안내를 이용하더라도
서비스가 정한 순서대로
모든 정보를 확인하도록 강제하지 않는다.


## UC-03. Advanced Information Access

초보자를 위한 안내 때문에
기존 전문정보 접근이 제한되어서는 안 된다.


## UC-04. Back Navigation

사용자는 주문 과정에서도
이전 단계로 돌아가
선택 내용을 변경할 수 있어야 한다.


---

# 7. Edge Cases

## Case 1. Guide Declined

사용자가 첫 구매 안내를 선택하지 않는다.

### Response

기존 종목 상세 화면을 그대로 이용한다.

구매 기능 및 전문정보 접근에는
제한이 발생하지 않는다.


---

## Case 2. Information Guide Partially Viewed

사용자가 일부 정보만 확인하고
구매하기를 선택한다.

### Response

나머지 정보 확인을 강제하지 않고
구매 단계로 이동한다.


---

## Case 3. Limit Order Not Immediately Executable

사용자가 원하는 가격을 직접 입력했지만
현재 거래 가능한 가격과 차이가 있다.

### Response

주문이 바로 체결되지 않을 수 있다는 점을
주문 전 확인할 수 있도록 한다.


---

## Case 4. User Changes Order Method

사용자가 주문 방식을 변경한다.

### Response

선택된 주문 방식과 관련 설명,
가격 입력 방식 및 최종 확인 정보가
변경된 선택에 맞게 업데이트되어야 한다.


---

# 8. Prototype Scope

초기 프로토타입에서는
핵심 문제 검증에 필요한 경험만 구현한다.


## Screen 1. Stock Detail

Purpose:

종목 정보 확인 및
첫 구매 안내 진입


Key Elements:

- 삼성전자
- 현재 가격
- 가격 변화 정보
- 주요 정보 영역
- 구매하기
- 첫 구매 안내


---

## Screen 2. Information Guide

Purpose:

구매 전에 확인할 수 있는
정보의 역할 안내


Key Elements:

- 가격 변화
- 최근 정보
- 기업 정보
- 상세 정보 접근
- 구매하기


---

## Screen 3. Order Method

Purpose:

주문 방식의 차이를
행동 중심으로 설명


Key Elements:

- 현재 거래 가능한 가격을 기준으로 구매
- 원하는 가격을 직접 정해서 구매
- 시장가 / 지정가 보조 표시


---

## Screen 4. Quantity

Purpose:

구매 수량과 예상 금액 확인


Key Elements:

- 선택한 주문 방식
- 수량
- 가격
- 예상 주문 금액


---

## Screen 5. Order Review

Purpose:

최종 주문 내용과
선택한 주문 방식 확인


Key Elements:

- 종목
- 수량
- 주문 방식
- 가격 또는 가격 결정 방식
- 예상 주문 금액
- 최종 확인


---

# 9. Prototype Test Tasks

프로토타입 완성 후
사용자에게 다음 과업을 제시한다.

> 삼성전자 주식 1주를
> 처음 구매한다고 생각해주세요.
>
> 필요한 정보를 확인하고
> 주문 직전까지 진행해주세요.


테스트에서는 다음 내용을 확인한다.


### Information Selection

사용자가 구매 전에
어떤 정보를 확인하는가?


### Information Understanding

각 정보가 무엇을 확인하기 위한 것인지
사용자가 자신의 말로 설명할 수 있는가?


### Order Understanding

선택한 주문 방식이
무엇을 의미하는지 설명할 수 있는가?


### Flow

안내 때문에 구매 과정이
불필요하게 복잡하거나 길어지지는 않는가?


### User Control

안내를 이용하지 않거나
일부만 확인하고도
자유롭게 다음 행동으로 이동할 수 있는가?


---

# 10. Validation Criteria

개선안의 검증에서는
단순히 주문 단계에 도달했는지만 확인하지 않는다.


## Completion

사용자가 별도의 진행자 도움 없이
주문 확인 단계까지 이동할 수 있는가?


## Understanding

사용자가 자신이 선택한
주문 방식의 의미를 설명할 수 있는가?


## Information Role

사용자가 구매 전에 제공된 정보가
각각 무엇을 확인하기 위한 것인지
구분할 수 있는가?


## Autonomy

사용자가 안내를 따르지 않더라도
자유롭게 정보를 탐색하고
구매 과정을 진행할 수 있는가?


## Neutrality

서비스의 안내가
특정 종목의 매수 여부나
투자 판단을 대신하지 않는가?


---

- 관심종목

- 투자자 수익 인증
- AI 종목 추천
- 종목 추천
- 주가 예측
- 포트폴리오 관리

# 12. Implementation Boundary

이번 개선안의 핵심 검증 범위는 다음 세 가지다.

### 1. Information Selection

첫 구매 사용자가
구매 전에 확인할 수 있는 정보의 역할을
이해할 수 있는가?


### 2. Contextual Understanding

별도의 도움말 탐색 없이
현재 선택의 의미를 이해할 수 있는가?


### 3. Purchase Understanding

사용자가 단순히 구매 과정을 완료하는 것을 넘어
자신이 어떤 방식으로 주문하고 있는지
이해할 수 있는가?


이 세 가지와 직접적인 관련이 없는 기능은
초기 구현 범위에서 제외한다.
