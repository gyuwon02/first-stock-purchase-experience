# Prototype Structure

## 1. Purpose

프로토타입에서는 첫 구매 사용자가 기존 증권 서비스 흐름 안에서

- 구매 전에 확인할 수 있는 정보의 역할
- 주문 방식에 따른 차이
- 자신이 선택한 주문 내용

을 이해할 수 있는지 검증한다.


---

## 2. Screen Flow

`01. Stock Detail`

→ `02. Order Method`

→ `03. Quantity`

→ `04. Order Review`

종목 상세에서는 첫 구매 안내의 OFF / ON 상태를 구분한다.

안내를 선택해도 별도의 화면으로 이동하지 않고
현재 화면 안에서 정보의 역할을 확인한다.


---

## 3. Stock Detail

**Purpose**

기존 종목 상세 경험을 유지하면서
첫 구매 사용자에게 정보 탐색의 맥락을 제공한다.

**Key Elements**

- 종목명 및 현재 가격
- 가격 변화 및 차트
- 상세 정보 탐색 영역
- 첫 구매 안내
- 구매하기

**Interaction**

- `살펴보기` → 현재 화면에서 안내 활성화
- `괜찮아요` → 기존 화면 유지
- `구매하기` → Order Method


---

## 4. Order Method

**Purpose**

주문 방식의 전문용어보다
각 선택에 따라 무엇이 달라지는지 먼저 이해하도록 한다.

**Key Elements**

- 현재 거래 가능한 가격을 기준으로 구매
- 원하는 가격을 직접 정해서 구매
- 각 방식의 차이
- 시장가 / 지정가 보조 표시

**Interaction**

주문 방식 선택 → `다음` → Quantity


---

## 5. Quantity

**Purpose**

구매 수량과 예상 주문 내용을 확인한다.

**Key Elements**

- 선택한 주문 방식
- 구매 수량
- 가격 또는 가격 결정 방식
- 예상 주문 금액

**Interaction**

수량 변경 → 예상 금액 반영 → `다음` → Order Review


---

## 6. Order Review

**Purpose**

최종 주문 전에
사용자가 자신이 선택한 내용을 다시 확인한다.

**Key Elements**

- 종목명
- 수량
- 주문 방식
- 가격 또는 가격 결정 방식
- 예상 주문 금액

실제 금융 거래는 수행하지 않는다.


---

## 7. Interaction Principle

첫 구매 안내는 기존 흐름을 대체하지 않는다.

사용자는 안내를 이용하거나,
일부만 확인하거나,
건너뛸 수 있다.

핵심은 정보를 줄이는 것이 아니라
현재 행동에 필요한 정보의 역할과 선택의 의미를
필요한 시점에 이해할 수 있도록 하는 것이다.
